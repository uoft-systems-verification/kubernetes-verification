# Goose mistranslates `:=` that shadows a variable used on its right-hand side

In Go, a variable declared by `x := e` (or `var x = e`) is in scope only
*after* the statement, so `e` sees the outer `x`. Goose allocates the new
variable *before* evaluating `e`, so `e` reads the new, zero-valued `x`.

Affects every short variable declaration: plain `:=`, `var`, `if`/`for`/`switch`
initializers, and multi-value `:=`. Not affected: `range` and
`switch x := x.(type)`, which evaluate the expression first.

Reproduced with perennial `mit-pdos/perennial@3fe5d0a95` (upstream `master`,
2026-09-01) and `uoft-systems-verification/perennial@45eb46d2b`.

## Reproduce

```bash
./run.sh          # goose pinned in ../go.mod; PERENNIAL=<checkout> to use another perennial
./run.sh clean
```

It runs `go test` (the Go behaviour), builds `goose` and `proofgen` (the
versions pinned in the enclosing `go.mod`, or from `$PERENNIAL`), translates this package into `gen/`, and checks
`proof/Repro.v` with Rocq. Needs Go and `rocq` with Perennial installed.

## Example

```go
func Define(x int) int {
	{
		x := x + 1
		return x
	}
}
```

Go: `Define(41) == 42`. Goose output:

```coq
Definition Defineⁱᵐᵖˡ : val :=
  λ: "x",
    exception_do (let: "x" := (GoAlloc go.int "x") in
    let: "x" := (GoAlloc go.int (GoZeroVal go.int #())) in   (* new x, too early *)
    let: "$r0" := ((![go.int] "x") +⟨go.int⟩ #(W64 1)) in     (* reads the new x = 0 *)
    do:  ("x" <-[go.int] "$r0");;;
    return: (![go.int] "x")).
```

## Results

| function (`repro.go`) | Go | translation (proved in `proof/Repro.v`) |
|---|---|---|
| `Define`: `x := x + 1` | `x + 1` | always `1` |
| `VarDecl`: `var x = x + 1` | `x + 1` | always `1` |
| `IfInit`: `if x := x + 1; x > 0` | `x + 1` or `0` | always `1` |
| `MultiRet`: `x, ok := pair(x)` | `x + 1` | always `1` (`pair` gets `0`) |
| `ForInit`: `for i, x := 0, x; ... { return x }` | `x` | always `nil` |

All specs have only `is_pkg_init` as precondition, so they are not vacuous.
They are partial correctness: each translated function returns the stated value
or does not return at all; either way it differs from Go.

## Cause

`defineStmt` in `goose/goose.go` calls `assignStmt`, whose output already
contains both the right-hand-side evaluation (`let: "$r0" := ...`) and the
stores, and then wraps the `GoAlloc` of each new variable around all of it.
The allocations need to go between the evaluation and the stores:

```coq
let: "$r0" := ((![go.int] "x") +⟨go.int⟩ #(W64 1)) in   (* outer x *)
let: "x" := (GoAlloc go.int (GoZeroVal go.int #())) in
do:  ("x" <-[go.int] "$r0");;;
```
